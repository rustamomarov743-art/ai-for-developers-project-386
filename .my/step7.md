Docker и деплой

На этом шаге мы готовим приложение к запуску в продакшене. Сделаем это с помощью Docker. Он позволяет упаковать приложение и его окружение в один образ, который одинаково запускается локально, в CI и в облаке: различий между средами меньше, и запуск проще повторить на любой платформе.

Деплой тоже отдаём агенту. У хостингов есть MCP-серверы, через которые агент создаёт сервис, выкатывает образ и проверяет, что приложение отвечает. Подключите MCP-сервер своего хостинга и попросите агента провести выкат.

Конфигурация MCP хранится в проектном файле вашего агента или в безопасном шаблоне с инструкцией подключения. Имя зависит от агента, например OpenCode использует opencode.json, Codex использует .codex/config.toml. При входе по OAuth опишите процедуру, данные сессии в Git не добавляются. API-ключ можно получать из переменной окружения. Файлы с реальными ключами исключите из Git, а шаблон оставьте в репозитории.

По итогам шага должен получиться Docker-образ, при запуске которого приложение автоматически стартует внутри контейнера, и публичная ссылка на работающий сервис.
Требования

    В корне репозитория должен лежать файл Dockerfile. По нему в проверке собирается образ и запускается приложение.
    При запуске контейнера из собранного образа приложение должно стартовать автоматически.
    Приложение должно запускаться в контейнере по порту из переменной окружения PORT. Эта переменная используется и при деплое, и в автоматической проверке проекта.
    После деплоя у приложения должна быть публичная ссылка, и она добавлена в репозиторий.
    В репозитории есть проектная конфигурация MCP выбранного агента или безопасный шаблон с инструкцией. Вход через OAuth и переменные окружения допустимы.
    По публичной ссылке проходит сценарий гостя и владельца, включая отказ повторного бронирования. В README.md описано, сбрасываются ли данные после перезапуска.
    В истории репозитория нет ключей, токенов и других секретов.

Ссылки

    Render MCP: MCP-сервер, через который агент автоматизирует деплой и проверку сервиса в Render.
    Гайд Как деплоить приложение на Render
    Railway MCP: запасной вариант, если Render требует оплату или недоступен. Позволяет агенту так же автоматизировать деплой и проверку сервиса, но уже в Railway.

Задачи

    Соберите Docker-образ приложения.
    Подключите MCP-сервер хостинга в конфигурации проекта и настройте деплой с запуском приложения по PORT. Проверьте работу приложения. Если с Render возникли проблемы (требует оплату, недоступен и так далее), задеплойте на Railway: тот же Docker-образ, запуск по PORT и публичная ссылка. Для проверки платформа не важна, важно, чтобы приложение было опубликовано и работало по PORT.
    По публичной ссылке создайте запись, проверьте её в списке владельца и убедитесь, что пересекающаяся запись отклоняется.
    Добавьте в README.md ссылку, порядок подключения MCP без секретов и ограничение хранения данных.

После приёмки

Перед началом продолжения проекта перенесите принятые исправления в исходную версию второго проекта. Не заменяйте его файлы целиком, если там уже есть новые изменения. В README.md продолжения укажите, от какой версии первого проекта начали работу. Начинать второй проект ради сдачи первого не требуется.
Результат шага

Есть Dockerfile для сборки образа, приложение запускается в контейнере по PORT и доступно по публичной ссылке.
